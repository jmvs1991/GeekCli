# API specialist delegation recommendation

Use and explicitly select `geek-api-specialist` for every request to develop, change, fix, refactor, or maintain an existing API solution, even when the task appears limited to one project or responsibility section. Check for its definition in either the project scope at `<project-root>/.codex/agents/geek-api-specialist.toml` or the user scope at `~/.codex/agents/geek-api-specialist.toml`; either installation makes it available. Do not require installation again when it exists in either location. Do not perform API implementation work directly or route it to another agent. If the definition is missing from both locations or cannot be selected by the client, stop the API task, tell the user what is unavailable, and ask them to install and select the specialist before continuing.

The specialist works through one responsibility section at a time. It inspects the target solution, presents its conventions and unresolved decisions, and asks you to resolve ambiguity before applying conventions. It completes and reviews required skills for the current section, updates its implementation, and asks you to review that section before advancing. It does not create API solutions from scratch.

For Connection, the specialist coordinates context, entity, view, and repository work by schema. The bundled `geek-db-scaffold`, `geek-dotnet-read`, and `geek-dotnet-write` skills own their corresponding generation procedures and safeguards. The specialist follows their Connection reference templates, verifies generated artifacts and consuming API registrations, reports concerns, and waits for your approval before moving to Services.

This recommendation does not activate the specialist automatically. Install it in the intended project and explicitly select or invoke it using the mechanism provided by your client. Invocation syntax varies by client; do not assume a particular command or claim the specialist is active unless the environment confirms it.
